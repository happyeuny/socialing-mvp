# 작업 계획: 마일스톤

- 날짜 일정은 없다. 순서와 마일스톤 끝 점검으로 진행한다.
- 진행 표시는 이 문서의 체크박스로 한다. 마일스톤을 끝내는 PR에서 체크한다.
- 스펙: [spec.md](spec.md) · 구조: [architecture.md](architecture.md) · 화면 경우 ID: [screen-cases.md](screen-cases.md)

## 1. 작업 규칙

1. **마일스톤 하나씩** 맡는다. 시작할 때 먼저 PR 단위 계획을 보여 주고, PM(EUNI)이 확인한 뒤 코딩한다.
2. **PR 하나는 작게**: 화면 하나 또는 DB 함수 하나 정도. PR 미리보기 배포에서 확인한 뒤 main에 합친다.
3. 시작할 때 `AGENTS.md`, 이 문서의 해당 마일스톤, 마일스톤이 가리키는 spec·architecture 절, 화면이면 DESIGN.md와 해당 와이어프레임·시안을 읽는다.
4. 상태 전환·권한 규칙은 DB 함수(RPC)에만 둔다. 화면 코드는 함수를 부르기만 한다.
5. 범위 밖 기능을 추가하지 않는다. 필요해 보이면 PR 설명에 "제안"으로만 적는다.

### 모든 PR의 완료 기준
- [ ] `npm run build`와 `npm run lint`가 통과한다
- [ ] 해당 기능의 E2E 테스트가 추가되고, 기존 E2E가 모두 통과한다 (Q1)
- [ ] 새 화면에 로딩·오류 상태가 있고, 오류에서 다시 시도·돌아가기가 된다 (Q2)
- [ ] 휴대폰 폭(390px)에서 가로 스크롤 없이 보인다
- [ ] 동작이 스펙과 달라졌다면 `docs/` 해당 문서를 같은 PR에서 고쳤다
